# FORMA — контекст для следующего чата

Состояние: 14 ноября 2026, продолжение настройки с подготовкой PR. Сначала прочитайте `AGENTS.md` и `docs/VERIFICATION.md`.

## Архитектура

Публичный статический русскоязычный лендинг презентаций, рассчитанный на GitHub Pages. Сборщика, package.json, серверного API, базы заказов, авторизации и CI workflow в доступном дереве нет. Не следует достраивать частный административный проект по предположениям.

- `index.html`: контент, SEO/social metadata, форма, портфолио, FAQ и dialog.
- `premium.css`: единственный подключённый CSS, тёмно-фиолетовая композиция, адаптивные пороги 1190/980/640/370 px, reduced motion.
- `style.css`: прежний дизайн, сейчас не подключён. Не удалять без отдельной задачи.
- `client.js`: меню, якоря, выбор формата, фильтры/карусель/диалог, валидация, подготовка брифа, копирование и Telegram deep link. Бриф формируется локально; пользователь сам подтверждает отправку в Telegram. Для длинного брифа предусмотрено копирование.
- Локальные WebP/JPG/SVG: обложки, портфолио, декоративная волна, favicon/social preview. `.nojekyll`, `robots.txt`, `sitemap.xml`: статическая публикация и индексация.
- `.codex/`: регистрации четырёх ролей и инструкции; наличие файлов не доказывает их загрузку облачным хостом.
- `tools/check_project.py`: автономная проверка целостности без сети, записи и зависимостей.
- `tools/browser_smoke.py`: реальные проверки локальной страницы в headless Chromium через Python Playwright, размеры 320/390/430/1440 px; блокирует внешние запросы. Артефакты в игнорируемом `work/browser/`, отчёт последнего запуска — `docs/browser-results.json`.

## Работа команды

Координатор планирует и сводит результаты. `ui_auditor` отвечает за UI/a11y, `qa_auditor` — логику и целостность, `release_auditor` — итоговый diff и доказательства. `frontend_implementer` — единственный исполнитель правок сайта, только по отдельному разрешённому заданию. UI и QA работают независимо; пересекающиеся дефекты объединяет координатор. Release проверяет их доказательства, а не повторяет аудит.

Для generic Cloud tasks передавайте полный текст инструкций роли явно. В доступном API есть task_name/message, но нет выбора agent_type/config_file. Для хостов, поддерживающих роли, в config зарегистрированы относительные пути к файлам. В новых задачах координатор самостоятельно выбирает роли по таблице маршрутизации в AGENTS.md, без повторного запроса названий у пользователя. Это политика координатора; автоматическое выполнение в новом чате ещё не наблюдалось.

Два новых агента без истории чата получили полный текст назначенных ролей, прочитали их файлы, вернули совпадающие SHA-256 и применили ограничения. Явная передача инструкций подтверждена; автоматическая загрузка role config хостом и sandbox enforcement остаются непроверенными.

## Ограничения и следующие задачи

Текущая задача разрешает инструкции, конфигурацию, документацию, проверки, коммит и push рабочей ветки, PR в main и отдельные GitHub Issues. Внешний вид, бизнес-логика и публикация неизменны. Разрешения на слияние нет.

1. Исправления формы и интерфейса вынесены в Issues #2–#7; приоритеты и доказательства — в `docs/VERIFICATION.md`. Устаревание брифа и приём пробелов уже воспроизведены в Chromium; исходники пока не исправлены.
2. Локальные Chromium проверки 320/390/430/1440 px, фильтра, dialog, FAQ, клавиатурного меню и формы выполнены. Дополнительно проверить реальные устройства/iOS, скринридер, контраст, обычный motion и полную навигацию карусели; сравнивать с референсами только при их наличии.
3. По отдельному согласованию решать порядок DOM/мобильного отображения и читаемость мелкого текста. iOS focus zoom остаётся гипотезой.
4. Проверить загрузку именно role config в новом поддерживающем её runtime; отдельно проверить sandbox enforcement. Generic spawning уже подтверждён, автоматическая привязка пока нет.
5. Перед будущей публикацией снова проверить свежесть веток и автоматические jobs. Эта задача разрешает push только рабочей ветки и не даёт разрешения на merge/deploy.
